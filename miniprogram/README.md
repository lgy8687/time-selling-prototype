# 时间售卖 · 微信小程序演示版

版本：`v0.7.0-mini`。这是在现有 React + Vite 原型旁新增的微信原生小程序，现阶段用于在微信开发者工具中体验时间表、发布和服务详情。网页原型仍在仓库根目录。

## 导入

1. 打开微信开发者工具，选择“导入项目”，目录选本文件夹 `miniprogram/`。
2. `project.config.json` 现使用开发者工具中已有的小程序测试号。需要正式发布时，须在开发者工具中替换为自己的正式 AppID。
3. 启动后进入“大厅”，底部可切换“大厅／时间表／发布／消息／我的”。

## 本版本能做什么

- 时间表共用一张可收放月历。B220 仅切换日历下方的“安排”或“时间块”；点日期更新下方内容，点月份标题回到当前月，左右滑动日历切换月份。整页滚动时月历逐渐裁切至当前周，并保持在顶部；反向滚动逐渐展开。每天先显示一条短标签，多余显示 `+N`。
- 日历下方的时间块用于精确排课。点相邻格可逐格选择一个连续时间段；再次点已选格可取消，长按时间格可拖选连续格。选中后点右侧标签，进入添加面板；面板用时间块选择开始与结束时间并保存。不相邻选格暂不支持。
- 添加面板的标签栏可新增常用标签，按当前“已安排／私人占用／开放时间”类型保存，并自动选中新标签。
- 每小时可选 `30+30`、`30+15+15`、`15+15+15+15` 三种分格。三格模式没有 20 分钟格。
- 常用标签在时间格右侧区域；在时间格右滑可暂时收起标签并放大时间格，左滑恢复。
- “我的”右上角进入独立设置页，可修改时间表起止时间、分格和常用标签，也可开启开发者模式。开启后各功能区直接显示可点击复制的 B 编号；设置页可查阅和复制全部 B/Z 编号。
- 新建的演示账户会在当天显示课程、私人占用和开放时间；仅当旧本机数据仍与原始三条演示安排完全一致时，会补入当天演示安排。已有用户自行编辑的时间不会被替换。
- 私人安排、已安排和开放时间共用本机事件集合；保存时检测冲突。可分享时间只展示未来且未与占用冲突的开放段。
- 发布首页分“时间售卖”和“时间求购”。售卖先选知识付费、跑腿代办、职业技能或情绪价值，再在表单里选具体类别。网约车、遛狗、跆拳道和陪聊提供可编辑示例；履历按需填写，示例中的方括号须改成真实经历才能本机发布。可另存自己的模板，模板不复制旧时间。求购可填写需求、期望日期和预算，保存在本机列表中。
- 发布页直接弹出时间块选时段，轻点连续选格、再点取消；长按 2 秒可设区间起点和终点。已占用时间不可选，已选时段与私人时间表共用本机事件数据。跑腿代办可选具体时段或完成窗口、多个指定地点或全城、每段接单上限；其他三大类可同时选择线上和线下、一对一和开团，并为每种组合分别定价，开团价格按每人计算。线下可协商或指定地点。
- 保存草稿和“本机发布”分开。本机发布会出现在这台设备的大厅；“我的发布”与大厅都打开同一张服务详情页，发布者额外看到编辑和买家时间预览入口。大厅还提供带三条示例履历和示例时段的服务卡，供首次打开时查看完整详情。我的页面可改昵称、上传本机头像，并查看发布、开放时间及工具入口。

## 还没有接入

所有数据目前只保存在设备本地。没有登录、跨设备同步、跨用户发布、真实消息、支付或真实预约。本机发布也不会在其他用户手机上出现。大厅中的示例人物与价格不是可购买服务。详情页的“选择时间”只演示买家流程，不生成订单，也不会扣减上限或确认成团。正式预约需要服务端统一时间库存、订单状态和数据库事务；切勿把本机冲突检查当成防重复预约的服务端保障。

网页原型的 `localStorage` 数据不会自动迁入微信小程序的本地存储。未来设计导入或迁移时，需要先做备份与数据映射。

## 维护

视觉沿用原型中的绿色、浅灰、亮黄和卡片圆角。版本号显示在“我的”和“设置”底部。`ui-registry.json` 登记 B/Z/C 交互编码；修改页面时同步更新登记。发布流程参考 Cal.com 的“服务类型关联可用时间”和 Sharetribe 的“发布者创建 listing、买家在同一 listing 查看并选择时间”的结构。只借鉴信息架构和交互，本版使用已有微信原生页面与本机存储，没有移植它们的服务端。参考：[Cal.com 事件类型说明](https://cal.com/scheduling/frequently-asked-questions)、[Sharetribe 可用时间说明](https://www.sharetribe.com/help/en/articles/8413212-how-availability-management-works)、[Sharetribe 服务市场教程](https://www.sharetribe.com/help/en/articles/9951125-how-to-set-up-a-service-marketplace-with-calendar-bookings)。

后续接入正式服务端时，建议按“账户与数据同步 → 时间库存及原子预约 → 公开发布和审核 → 交易与通知”的顺序推进。正式上线所需的主体资质、类目及交易规则应按届时微信官方要求核对。
